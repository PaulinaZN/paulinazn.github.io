Laboratorio — Arquitectura Cloud (AWS)

De servidor único a arquitectura de alta disponibilidad

Tomé una aplicación desplegada en una única instancia EC2 y la llevé a una arquitectura de alta disponibilidad con balanceo de carga, autoescalado y monitoreo activo. Validé el ciclo completo — alarma → escalado → recuperación — sometiendo la infraestructura a carga real para comprobar que respondía sola, sin intervención manual.

Desafío principal

La aplicación original dependía de una única instancia EC2: si esa instancia fallaba o el tráfico superaba su capacidad, el servicio se caía o se degradaba, sin ningún mecanismo de recuperación automática.

Solución propuesta

Migrar de una instancia aislada a un Auto Scaling Group detrás de un Application Load Balancer, con alarmas de CloudWatch que disparan el escalado según el consumo de CPU, permitiendo que la infraestructura reaccione sola ante picos de carga o fallos.

Herramientas técnicas utilizadas

AWS EC2 (Amazon Linux), Application Load Balancer, Auto Scaling Group y Amazon CloudWatch para métricas y alarmas.

Principales aprendizajes

Entender en la práctica la diferencia entre escalar verticalmente y horizontalmente, cómo un balanceador distribuye tráfico entre instancias saludables, y cómo diseñar un ciclo de monitoreo que reacciona sin intervención manual.

Impacto

Validé de forma cualitativa que el ciclo completo funcionaba de punta a punta: al generar carga, la alarma se disparaba, se sumaban instancias nuevas al grupo y el tráfico se redistribuía automáticamente sin caídas del servicio.

Habilidades técnicas aplicadas

Arquitectura de alta disponibilidad, balanceo de carga, autoescalado, monitoreo y alertas, pensamiento en resiliencia de sistemas.

Por qué elegí este proyecto

Porque va más allá de "hacer que algo funcione": obliga a pensar en qué pasa cuando algo falla o cuando la demanda crece, que es exactamente el tipo de razonamiento que se espera de un perfil cloud, incluso junior.

  • Migración desde una única instancia EC2 hacia un Auto Scaling Group.
  • Configuración de un Application Load Balancer para distribuir el tráfico entre instancias.
  • Métricas y alarmas en CloudWatch para disparar el escalado automático según demanda.
  • Validación del ciclo completo — alarma → escalado → recuperación — sometiendo la infraestructura a carga real.
